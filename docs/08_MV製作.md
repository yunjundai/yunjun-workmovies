# 08 歌曲 MV 製作

> 操作步驟與指令在 [`pipeline/template_mv/README.md`](../pipeline/template_mv/README.md)。這份文件記錄「為什麼這樣設計」和第一次實作的數字，給下一支 MV 規劃時參考。

## 第一次實作：〈把青春唱成光〉（2026-10-29～30）
- 4:33、70 鏡（唱 37／奏 7／手 5／景 21），兩位小學生主唱＋電吉他，寫實校園風。
- 首幀：ChatGPT 桌面版（GPT-6.1 Sol）定妝照 5、場景母版 10、首幀 70，約 3 小時（中間碰到一次使用上限）。
- H3：Colab G4。試跑 5 鏡 8 分鐘；整批 65 鏡約 1.5 小時；重做 12＋4＋4＋1 鏡。
- 剪接：本機 ffmpeg 約 5 分鐘。

## 設計決定
| 問題 | 決定 | 理由 |
|---|---|---|
| 聲音 | 成片放原曲；唱的鏡用分離人聲當 H3 `fixed` 音軌 | H3 只負責嘴型；原曲不動，不會有音質或節拍問題 |
| 不唱的鏡 | 給靜音音軌 | 不給的話角色會自己開口 |
| 短鏡（2 秒導歌） | H3 至少生 4 秒，剪接只取前段 | H3 太短不穩 |
| 合唱 | dialogue 加 `with`（h3_shot.py） | 實測兩人嘴都會動 |
| 回憶與現在 | 換服裝（演出服／制服）＝不同角色 key | 觀眾一眼分得出時間線；ChatGPT、H3 也比較不會混 |
| 鏡表時間 | `tools/mv_song.py`：demucs 分離＋whisper 取時間＋動態規劃對齊歌詞 | whisper 聽歌詞文字常錯，但時間大致準；文字一律用歌詞檔 |
| 生成後段壞掉 | `pin_last`（唱）／`src_max`（不唱） | 重抽 3–4 次常常還是壞，換方法比較快 |

## 歌詞從 Word 轉成 lyrics.txt
```
python3 -c "import zipfile,re,sys;x=zipfile.ZipFile(sys.argv[1]).read('word/document.xml').decode();open('assets/lyrics.txt','w').write('\n'.join(''.join(re.findall(r'<w:t[^>]*>(.*?)</w:t>',p)) for p in re.findall(r'<w:p[ >].*?</w:p>',x,re.S)))" 歌詞.docx
```
第一行若是歌名，刪掉或改成 `# 歌名`。

## 下一支 MV 可以再改進的地方
- 對嘴準確度還沒有自動檢查：可以把 H3 輸出的嘴部動作和人聲能量做相關比對，抓出沒張嘴的鏡。
- 有些副歌重複的鏡頭（同一句歌詞出現 2–3 次）可以重用同一段 H3，省 Colab 時間。
- 舞台觀眾、回憶群像這類「景」鏡，H3 最容易出問題；可考慮改用慢速推近的靜態圖（Ken Burns）代替。
